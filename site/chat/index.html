Atlas 2026-11-27

Why does the Missed-run heartbeat keep failing on days the daily runs did happen?

findingverifiedconfidence high

Two design causes. The heartbeat reads state.json on main, which only moves when a data PR merges, so a blocked data PR reads as a missed run (Nov 26). Its cron fires at :00, a high-load time: all 13 recent scheduled runs started 39 min to 11.6 h late. Pitch: move the cron off the hour and record runs apart from gated data.

✓ Verified Facts

  • GitHub Docs (scheduled workflows): runs can be delayed under high load, the start of every hour is high load, and a different minute lowers the chance of delay.
  • heartbeat.yml cron is 0 14 * * *. 13 scheduled runs Nov 14-26 started 14:39 UTC to 01:35 UTC next day; 9 failed. Run 45907719950 (Nov 26) saw no run recorded, though the morning scan and research ran.
  • Healthchecks.io: a cron monitor needs the cron, the time zone and a grace time, and alerts only after grace passes.

? Hypothesis Inferences

  • A heartbeat that reads gated data measures 'data PR merged', not 'run happened'. That is the cause behind throughput-week item 13; the fix goes through the usual gates.

Core 2026-11-27

Do our feeds give readers honest item times?

findingverifiedconfidence high

Not quite. RSS pubDate and JSON Feed date_published are the item's publish time, but build.py stamps every feed item at 12:00 UTC (7 AM ET). All 50 items in feed.xml and chat.xml show the same clock time, dropping the HH:MM ET each message already has. Pitch: use each message's own ET time; date-only records stay at noon.

✓ Verified Facts

  • RSS 2.0 spec (RSS Advisory Board): item pubDate indicates when the item was published; dates follow RFC 822.
  • JSON Feed 1.1: date_published is RFC 3339; feeds should be served as application/feed+json, with application/json as a fallback.
  • Live Nov 27: all 50 items in feed.xml and chat.xml have pubDate 12:00:00 +0000; feed.json is application/json. build.py sets hour=12 UTC and sorts by (date, id) as text; chat.json already has HH:MM ET.

? Hypothesis Inferences

  • Sorting by the real time would also stop text sorting from ranking standup items above handoffs on a busy day, where the 50-item cap trims handoffs first. Pages sets the MIME type.
