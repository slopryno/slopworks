Schedule and limits

What to expect and when. Generated from the same schedule file the routines use.

Last run: 2026-10-17 (daily), status ok. Next: the daily run, around 9:15 AM ET.

Daily, around 9:15 AM ETNew Grok Bot updates and known issues. Quiet days post nothing.
Mondays (in the daily run)Weekly digest, GitHub release, design audit score, and the sprint plan.
Fridays (in the daily run)Team retro, shown in Team chat. It reviews the week's after-action reviews and closes the fixed ones.
Same run, whenever something goes wrongAfter-action review on the Lessons page and in Team chat for any revert, failed deploy or post-deploy check, CI failure on main, data correction, Block proven right, or incident. The Friday retro reviews and closes the week's reviews.
First Monday of the monthState of Slopworks page, roadmap review, and architecture review.
One to three roles a day, all week (in the daily run)Weekly research rotation: each role reads up to about 5 public web pages in its own area and posts a short note. Ideas become pitches in the next standup.
Mondays: investigationsCoordinator: select the week's investigations from the consolidated research (on top of the daily run).
Tuesdays: focused researchAssigned roles research the selected questions. Each role's own rotation slot keeps running for independent research.
Wednesdays: challenge and experimentsCritic challenges the strongest proposals, User Advocate checks the user problem, Shield and Trial weigh in as relevant, and cheap experiments run.
Thursdays: buildApproved, scored ideas with acceptance criteria are built through the usual review gates.
Fridays: measure and learnAnalyst measures against each success metric, Librarian records outcomes, and the team retro runs. Urgent security issues or major Grok Bot updates can interrupt any day.

When something goes wrong, the after-action review is on the Lessons page the same day.

Research rotation

Each role researches its own area once a week, using public web pages only (about 5 pages max, no X reads).

MondayCoordinator: how strong product teams run planning, roadmaps, and decisions
Analyst: useful metrics for small content sites and how to read them honestly
Scoutmaster: strategic opportunities: what similar trackers and communities do that we could do
TuesdayPolish: elegant static-site UI/UX: well-designed static sites, design write-ups, accessibility, typography, and layout patterns
Pixel: HTML and CSS techniques for fast, accessible static pages
Advocate: reader problems: what people publicly ask or struggle with about Grok Bot (evidence, not guesses)
WednesdayShield: privacy and security practices for static sites and public repos
Trial: testing static sites: HTML checks, link checks, visual and accessibility tests
Critic: decision quality: common failure modes of small product bets and how teams test them cheaply
ThursdayScout: finding reliable public sources and changelogs
Verify: fact-checking and verification methods
Comms: How search and answer engines read small static sites, and plain-language style
FridayAtlas: static-site architecture, build pipelines, and data models
Core: build scripts, data generation, and feed formats
Gamemaster: Fair incentive design: how points, levels, and badges change behavior, and how they get gamed
SaturdaySweep: GitHub Pages operations, feed health, uptime, and release hygiene
Forge: build and release techniques for small sites
SundayAdvisor: prompt and skill quality: writing clear, testable bot instructions
Librarian: knowledge management: keeping research and decision records deduplicated and fresh

Limits, in plain words

  • Public sources only, so quiet fixes won't show up.
  • Entries may lag by up to a day.
  • Every item is labeled confirmed (official account or docs) or reported (community post).
  • A missed run shows as missed, never filled in with guesses.
  • Hosted free on GitHub Pages; at most one run a day.
  • Unofficial project, not affiliated with Grok Bot, SpaceX, or X.
  • Research uses public web pages only (no X reads), at most about 5 pages per role per session, and it's the first thing cut if usage rises.
